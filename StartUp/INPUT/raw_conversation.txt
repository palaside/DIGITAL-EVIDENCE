Smart Gap Search: หาก validateCut ส่งค่าเป็น false (คือมีการทับซ้อน) ระบบจะไม่ยอมตัดตรงนั้น แต่จะย้อนกลับไปหา Gap Valley (ช่วงว่างระหว่างบับเบิ้ลที่ใกล้ที่สุด) แทน

Tail Fragment Prevention: กฎการรวมเศษหน้าจะช่วยป้องกันไม่ให้หน้ากระดาษสุดท้ายมีแชทแค่ 1-2 บรรทัด ซึ่งดูไม่เป็นมืออาชีพและเปลืองทรัพยากรหลักฐาน

ขยายความเรื่อง การหา "Gap Valley" (จุดว่างระหว่างข้อความ) เลยครับ เพราะนี่คือ "หัวใจ" ที่ทำให้โปรแกรมของคุณฉลาดกว่าการแคปภาพหน้าจอธรรมดา

การหา Gap Valley คือการค้นหาพิกัด Y ที่ "ปลอดภัยที่สุด" ในการตัดแบ่งหน้า โดยมีขั้นตอนเชิงตรรกะดังนี้ครับ:

1. นิยามของ Gap Valley
Gap Valley คือช่วงพิกัด Y ที่ไม่มีวัตถุใดๆ ครอบอยู่ (ไม่มี Text Bubble, ไม่มีรูปภาพ, ไม่มี Sticker) ซึ่งเป็นพื้นที่ว่างที่โปรแกรมสามารถทำการ "ตัด" ได้โดยไม่ทำให้ข้อมูลแหว่งครับ

2. ขั้นตอนการหา (Algorithm Implementation)
คุณสามารถใช้เทคนิค "Horizontal Scan" หรือการสำรวจพื้นที่ว่างตามลำดับความสำคัญ (Priority) ได้ดังนี้:

JavaScript
/**
 * หาจุดตัดที่ปลอดภัยที่สุด (Gap Valley)
 * @param {Array} objects - รายการวัตถุทั้งหมด
 * @param {number} targetY - พิกัดที่อยากจะตัด (จุดที่เกินขอบ A4)
 * @param {number} searchRange - ระยะที่จะให้ระบบขยับหา (เช่น 200px ขึ้นไปข้างบน)
 */
function findGapValley(objects, targetY, searchRange = 200) {
    // 1. เรียงลำดับวัตถุตามพิกัด Y เพื่อให้ง่ายต่อการตรวจสอบ
    let sortedObjects = objects.sort((a, b) => a.yStart - b.yStart);

    // 2. ค้นหาช่องว่างในช่วงที่กำหนด (ถอยหลังขึ้นไปจากจุดตัด)
    for (let y = targetY; y > targetY - searchRange; y--) {
        let isOccupied = sortedObjects.some(obj => y >= obj.yStart && y <= obj.yEnd);
        
        // ถ้าไม่พบวัตถุใดๆ ครอบที่พิกัด y นี้ แสดงว่านี่คือ Gap Valley!
        if (!isOccupied) {
            return y; 
        }
    }
    
    // 3. กรณีไม่เจอ Gap Valley ในระยะที่กำหนด (fallback)
    return null; 
}
3. กลยุทธ์การตัดสินใจเลือกจุดตัด (Priority Rules)
ไม่ใช่แค่ช่องว่างไหนก็ได้ที่ตัดได้ แต่การทำหลักฐานดิจิทัลให้ดูเป็นมืออาชีพ คุณควรให้คะแนน (Weight) กับจุดตัดครับ:

คะแนนสูงสุด (High Priority): ช่องว่างระหว่าง "คนคุย" (Sender Switch) หรือ "Time Stamp" (เช่น ข้อความบอกเวลา 10:30 น.) นี่คือจุดที่คนอ่านรู้สึกเป็นธรรมชาติที่สุดในการขึ้นหน้าใหม่

คะแนนกลาง (Medium Priority): ช่องว่างระหว่างบับเบิ้ลของคนเดียวกัน

คะแนนต่ำสุด (Low Priority): จุดที่ต้องฝืนตัด (เช่น ภายในประโยคที่ยาวมาก)

ข้อควรระวังในการพัฒนา (Pro Tips):
The "Too Small" Gap: ต้องเช็คด้วยว่า Gap ที่เจอมีขนาดใหญ่พอที่จะตัดไหม (เช่น ต้องสูงอย่างน้อย 10-20px) ถ้า Gap แคบเกินไป อาจจะดูเหมือนภาพตัดขาดแบบน่าเกลียด ให้ข้ามไปหา Gap ที่กว้างกว่า

Visual Continuity (ลูกศรเชื่อม): เมื่อคุณเลือกจุดตัดได้แล้ว แนะนำให้โปรแกรมวาด "ลูกศรตัวหนอนสีเทาจางๆ" หรือ "สัญลักษณ์ต่อเนื่อง" ไว้ที่ขอบล่างของหน้ากระดาษ และขอบบนของหน้าถัดไป เพื่อให้กรรมการหรือผู้อ่านรู้ว่าแชทนี้ยังไม่จบนะครับ

ก้าวต่อไป:

อยากให้ผมช่วยออกแบบ "Weight/Scoring System" สำหรับการให้คะแนนช่องว่าง (เช่น ให้คะแนนช่องว่างตรงจุดเปลี่ยนผู้พูดสูงที่สุด) ไหมครับ?

หรือจะข้ามไปออกแบบ "Fallback Logic" (กด 2) เพื่อป้องกันกรณีที่หา Gap ไม่เจอจริงๆ ครับ?

แนวคิดอะไร ที่ เหมือนเราเลือกรูป ว่าขนาดประมาณนี้ หรือลดลง/เพิ่มขึ้น  แล้วก็ฟิต A4 
แนวคิดที่เหมือนกับการเลือกรูปว่าขนาดประมาณนี้ หรือลดลง/เพิ่มขึ้น แล้วก็ฟิต A4 นั้นคือแนวคิดของ "Smart Image Layouting" หรือ "Adaptive Image Composition" ครับ

แนวคิดนี้ไม่ได้หมายถึงการแคปภาพหน้าจอธรรมดา แต่เป็นระบบที่ "เข้าใจ" สัดส่วนและขนาดของภาพที่แคปมา เพื่อนำไปจัดวางลงในพื้นที่เป้าหมาย (เช่น กระดาษ A4) อย่างเหมาะสมที่สุด โดยมีองค์ประกอบสำคัญ 3 ส่วนดังนี้ครับ:

1. ระบบจัดการสัดส่วนภาพ (Adaptive Aspect Ratio Management)
นี่คือหัวใจสำคัญครับ เมื่อคุณเลือกพื้นที่หรือขนาดภาพ ระบบจะต้องมี logic ในการคำนวณ:

Fit to Page: โปรแกรมจะขยายภาพที่แคปมาให้ใหญ่ที่สุดโดยยังคงสัดส่วนเดิมไว้ และไม่เกินขอบกระดาษ A4 (ไม่ว่าภาพจะแนวตั้งหรือแนวนอน)

Smart Guides/Magnetic Guides: เวลาคุณลากภาพมาวาง โปรแกรมจะมีเส้น "Magnetic Guides" (เส้นประหรือจุดจางๆ) ที่คอยดึงภาพให้ snap เข้าหากึ่งกลางหรือขอบกระดาษโดยอัตโนมัติ เพื่อให้งานจัดหน้าดูเป็นมืออาชีพ

2. เครื่องมือที่แนะนำสำหรับการพัฒนา (Tech Stack)
หากคุณต้องการสร้างความสามารถนี้ โปรแกรมบน Windows ที่คุณกำลังพัฒนาด้วย JavaScript/Electron แนะนำให้ใช้เครื่องมือเหล่านี้ครับ:

Fabric.js: (สำหรับ Web-based Renderer ใน Electron) เป็น Canvas Library ที่ทรงพลังที่สุดสำหรับการทำ Object Manipulation (ลาก, วาง, ย่อ, ขยาย, หมุน) คุณสามารถกำหนดพื้นที่ Canvas ให้มีสัดส่วนเท่ากับ A4 และจัดการภาพที่แคปมาในรูปแบบ Object ได้อย่างอิสระ

jsPDF: หลังจากจัดวางภาพลงบน Canvas เสร็จแล้ว คุณต้องใช้ jsPDF เพื่อ Export ออกมาเป็นไฟล์ PDF ที่พร้อมพิมพ์ด้วยขนาด A4 จริงๆ โดยคุณสามารถกำหนด DPI และสัดส่วนกระดาษได้แม่นยำ

Layout Presets: มี Template ให้เลือก เช่น 1 ภาพเต็มหน้า, 4 ภาพแบ่ง 4 ส่วน, หรือแบบบันทึกการประชุม (Meeting Minutes) เพื่อให้ผู้ใช้กดวางได้ทันทีโดยไม่ต้องลากเองทั้งหมด

2. การจัดการวัตถุ (Capture & Composition Phase)
Import: เมื่อ User ลากภาพที่แคปมาวางในโปรแกรม:

Auto-Scale: ระบบตรวจสอบขนาดภาพ หากภาพใหญ่เกินไป ให้ย่อสเกลลงเหลือ 80% ของหน้ากระดาษโดยอัตโนมัติ (รักษา Aspect Ratio)

3. การปรับแต่งและตรวจสอบ (Validation Phase)
Manual Adjustment: ผู้ใช้สามารถลาก ขยาย หรือย่อขนาดภาพได้ตามต้องการ โดยระบบจะคอยเช็ค Collision Detection ตลอดเวลา หากขยับไปทับกับวัตถุอื่นหรือขอบกระดาษ ระบบจะแสดงเส้นนำทาง (Smart Guides) ให้เห็น

Integrity Gate: ก่อนที่จะเปลี่ยนหน้าหรือสรุปงาน โปรแกรมจะรัน Validation กฎเหล็ก (ห้ามข้อมูลซ้ำ, ห้ามผ่ากลางข้อความ, ห้ามหน้าว่าง) หากผ่านฉลุย ระบบจะขึ้นเครื่องหมาย "ผ่านเกณฑ์" ให้ผู้ใช้สบายใจ

4. การส่งออก (Export Phase)
PDF Generation: เมื่อจัดวางครบทุกหน้าแล้ว โปรแกรมรวบรวม Canvas ของแต่ละหน้าเข้าด้วยกัน

Watermarking/Annotation: วาดเลขหน้า ประทับตราหลักฐาน หรือลูกศรเชื่อม (Continuation Indicator) ลงไปในชั้นบนสุดของ PDF

Final Output: บันทึกออกมาเป็นไฟล์ PDF ชุดเดียวที่มีความคมชัดสูง (300 DPI)

ในวงการพิมพ์เอกสารมาตรฐานสากล 300 DPI (Dots Per Inch) คือค่ามาตรฐานที่ถือว่า "คมชัด" (Print-ready)

ขนาด A4 (มม.): 210 x 297 มม. หรือประมาณ 8.27 x 11.69 นิ้ว

เมื่อคำนวณเป็นพิกเซลที่ 300 DPI:

ความกว้าง: 8.27×300≈2,480 พิกเซล

ความสูง: 11.69×300≈3,508 พิกเซล

สรุป: Canvas ในโปรแกรมของคุณควรถูกกำหนดขนาดให้ได้ค่านี้ เพื่อรองรับการพิมพ์ที่คมชัดที่สุด

2. วิธีคำนวณ Scale Factor เพื่อให้ภาพไม่แตก
หากภาพที่แคปมาจากหน้าจอ (ซึ่งมักจะเป็น 72 หรือ 96 DPI) แล้วคุณนำมาวางบน Canvas ขนาด 300 DPI ภาพจะดูเล็กลงมาก ดังนั้นคุณต้องมี Logic การทำ Smart Upscaling:

JavaScript
// Logic คำนวณ Scale เพื่อให้ภาพพอดีกับพื้นที่และคงความคมชัด
function calculateOptimalScale(imgWidth, imgHeight, targetAreaWidth, targetAreaHeight) {
    // คำนวณอัตราส่วนเพื่อไม่ให้ภาพเสียสัดส่วน (Aspect Ratio)
    let ratio = Math.min(targetAreaWidth / imgWidth, targetAreaHeight / imgHeight);
    
    // คืนค่า Scale ที่เหมาะสม
    return ratio; 
}
3. กฎเหล็กของ "หลักฐานดิจิทัล" ที่ห้ามมองข้าม
ห้ามทำ Interpolation ที่รุนแรง: อย่าใช้ฟิลเตอร์ที่ทำให้ภาพเบลอ (เช่น Bilinear Interpolation) เพราะจะทำให้ข้อความอ่านยากขึ้น ให้ใช้การ Scaling แบบ "Nearest Neighbor" หรือ "Lanczos" (ซึ่งไลบรารีอย่าง Sharp หรือ Canvas ระดับสูงรองรับ) เพื่อคงขอบอักษรให้คมชัดที่สุด

Metadata Integrity: ในการทำหลักฐาน แนะนำให้ใส่ "Footprint" ไว้ที่มุมล่างของหน้ากระดาษ (เช่น ชื่อไฟล์ต้นฉบับ, วันที่แคป, และค่า Hash ของไฟล์ภาพ) เพื่อยืนยันว่าภาพนี้เป็นต้นฉบับไม่ได้ถูกตัดต่อ

ข้อแนะนำในทางปฏิบัติสำหรับโปรแกรมคุณ
DPI Awareness: บน Windows โปรแกรมของคุณต้องรับค่า devicePixelRatio จากหน้าจอ User มาคำนวณด้วย มิฉะนั้นภาพที่แคปมาอาจมีความละเอียดต่ำกว่าความเป็นจริง

PDF Library: เมื่อใช้ jsPDF ในการ Export อย่าลืมตั้งค่าความละเอียดของภาพที่ส่งเข้าไปใน PDF ให้ตรงกับ 300 DPI ตามที่คำนวณไว้

นี่คือ Pseudo-code สำหรับการทำโปรโตไทป์ระบบ "ลาก วาง ย่อ ขยาย" ด้วย Fabric.js โดยเน้นไปที่การควบคุม Object (ภาพที่แคปมา) ให้อยู่ในขอบเขตที่ต้องการครับ

Pseudo-code: Object Manipulation System (Fabric.js)
JavaScript
// 1. ตั้งค่า Canvas ขนาด A4 (ที่ 300 DPI: 2480 x 3508)
const canvas = new fabric.Canvas('a4-canvas', {
  width: 827,  // ปรับ Scale เพื่อการแสดงผลบนหน้าจอ
  height: 1169,
  backgroundColor: '#f0f0f0'
});

// 2. ฟังก์ชันเพิ่มภาพที่แคปมาลงหน้า Canvas
function addCaptureToCanvas(imageUrl) {
  fabric.Image.fromURL(imageUrl, function(img) {
    // ตั้งค่า Property ให้ภาพลากและย่อขยายได้
    img.set({
      left: 50,
      top: 50,
      scaleX: 0.5, // ค่าเริ่มต้น
      scaleY: 0.5,
      hasControls: true, // เปิดโหมดจับยืดขยาย
      lockRotation: true, // ล็อคการหมุน (ถ้าต้องการความเป็นทางการ)
      borderColor: 'blue',
      cornerColor: 'blue'
    });

    // 3. กฎการควบคุม (Boundary Enforcement)
    img.on('moving', function(e) {
      // ป้องกันไม่ให้ลากภาพออกนอกขอบกระดาษ A4
      const obj = e.target;
      if (obj.left < 0) obj.set({ left: 0 });
      if (obj.top < 0) obj.set({ top: 0 });
      // เช็คขอบขวา/ล่าง ...
    });

    canvas.add(img);
  });
}

// 4. ฟังชั่นก์สั่งย่อ/ขยาย (Zoom/Scale)
function scaleSelectedObject(factor) {
  let activeObj = canvas.getActiveObject();
  if (activeObj) {
    activeObj.scale(activeObj.scaleX * factor);
    canvas.renderAll();
  }
}
ทำไม Code นี้ถึงเป็นรากฐานที่ดี?
Encapsulation: ทุกภาพที่แคปมาจะกลายเป็น fabric.Image object ที่จัดการตัวเองได้ (มีพิกัด, สเกล, สถานะ)

Event-Driven: การใช้ img.on('moving') ช่วยให้คุณใส่ "Logic อัจฉริยะ" เช่น การทำ Snap-to-Grid หรือการแจ้งเตือนเมื่อลากไปทับกับวัตถุอื่น ได้ทันทีแบบ Real-time

Safety First: การล็อค lockRotation: true ช่วยให้หน้าตาของเอกสารหลักฐานดูเป็นมาตรฐานเดียวกันเสมอ ไม่เอียงไปมา

รับทราบครับ การทำ Fallback Logic คือขั้นตอนที่สำคัญที่สุดในการสร้าง UX ที่ดี เพราะแอปที่ "ฉลาด" ไม่ควรล่มหรือค้างเมื่อเจอสถานการณ์ที่วิเคราะห์ไม่ได้ แต่ควรมี "แผนสำรอง" ที่ทำให้ผู้ใช้งานยังทำงานต่อไปได้ครับ

ผมขอเสนอแนวคิด "Graceful Degradation" (การลดระดับความสามารถอย่างนุ่มนวล) สำหรับระบบนี้ครับ:

แนวคิด Fallback Logic: แผนสำรอง 3 ระดับ
เมื่อระบบอัจฉริยะ (Smart Layout/Snap) ทำงานผิดพลาด หรือเจอข้อมูลที่ซับซ้อนเกินกว่าจะคำนวณจุดตัดที่ปลอดภัยได้ ให้โปรแกรมทำงานตามลำดับนี้ครับ:

ระดับที่ 1: การเตือนและแนะนำ (Soft Intervention)
หากระบบตรวจพบว่าสิ่งที่ User กำลังทำ "เสี่ยง" ต่อการผิดกฎ (เช่น ลากภาพทับข้อความสำคัญ) แต่ยังไม่ถึงขั้นวิกฤต:

Action: แสดง Smart Guide หรือ Highlight สีส้ม/แดงจางๆ ที่จุดที่มีปัญหา

Feedback: ขึ้น Tooltip แจ้งเตือนสั้นๆ เช่น "ตำแหน่งนี้อาจทับข้อมูลสำคัญ ลองขยับไปทางขวาเล็กน้อย"

ระดับที่ 2: การถอยกลับสู่โหมด Manual (Semi-Automatic Mode)
หากระบบพยายาม Snap หรือย่อขยายภาพแล้วแต่ค่าความเชื่อมั่น (Confidence Score) ต่ำเกินไป (เช่น ข้อมูลซ้อนทับกันซับซ้อนจนอัลกอริทึมงง):

Action: ยกเลิกการ Snap อัตโนมัติในทันที แล้วเปลี่ยนสถานะของ Object นั้นเป็น "Free-move"

Logic:

JavaScript
if (confidenceScore < threshold) {
    obj.set({ lockMovementX: false, lockMovementY: false });
    showNotification("ไม่สามารถจัดวางอัตโนมัติได้ กรุณาปรับตำแหน่งด้วยตนเอง");
}
ระดับที่ 3: โหมดฉุกเฉิน (Safe Mode / Pixel-level Fallback)
กรณีที่ระบบ Smart Layout พังจริงๆ (เช่น ข้อมูลในหน้า A4 แน่นเกินไปจนหา Gap Valley ไม่เจอ):

Action: ระบบจะหยุดความพยายามแบ่งหน้าแบบอัจฉริยะ และสลับไปใช้ "Standard Pixel-level Pagination" (คือการตัดแบบดั้งเดิมตามขนาดพื้นที่ที่เหลือในหน้ากระดาษจริงๆ)

Visual Cue: ใส่เส้นประหนาๆ ที่จุดตัด พร้อมสัญลักษณ์ "Manual Cut" เพื่อให้ผู้ใช้ทราบว่าจุดนี้ระบบไม่ได้คำนวณให้ และสามารถกดแก้ไขเองได้ภายหลัง

โครงสร้าง Code สำหรับ Fallback Manager
JavaScript
function handleDropOrMove(obj) {
    try {
        if (isLayoutSafe(obj)) {
            applySmartLayout(obj); // ระบบอัจฉริยะทำงาน
        } else {
            throw new Error("Layout_Conflict");
        }
    } catch (error) {
        if (error.message === "Layout_Conflict") {
            // Fallback Logic: ปลดล็อกอิสระและแจ้งเตือน
            obj.set({ stroke: 'red', strokeWidth: 2 }); // เตือนด้วยสี
            showManualCorrectionPanel(); // เปิดเมนูช่วยแก้ไขให้ผู้ใช้
        }
    }
}

นี่คือจุดที่คุณจะเริ่มใส่ "นิ้วอัจฉริยะ" ที่เราคุยกันครับ:

JavaScript
const { fabric } = require('fabric');
const { jsPDF } = require('jspdf');

// 1. สร้าง Canvas ขนาด A4 (จำลอง)
const canvas = new fabric.Canvas('a4-canvas', {
  width: 595, // สัดส่วน A4
  height: 842,
  backgroundColor: '#fff'
});

// 2. ฟังก์ชันเพิ่มภาพ (เตรียมรับภาพจากระบบ Capture)
function addChatImage(url) {
  fabric.Image.fromURL(url, (img) => {
    img.scaleToWidth(500); // จัดขนาดให้พอดีหน้า
    canvas.add(img);
    canvas.renderAll();
  });
}

// 3. ฟังก์ชัน Export เป็น PDF (หัวใจหลักของหลักฐาน)
function exportToPDF() {
  const dataURL = canvas.toDataURL({ format: 'jpeg', quality: 1.0 });
  const doc = new jsPDF('p', 'mm', 'a4');
  doc.addImage(dataURL, 'JPEG', 0, 0, 210, 297);
  doc.save('evidence.pdf');
}

ฟังก์ชันดึงภาพเข้าโปรแกรม (Drag and Drop Handler)
ในไฟล์ src/renderer.js ให้เพิ่มโค้ดส่วนนี้เพื่อให้โปรแกรมของคุณรองรับการลากไฟล์ภาพจากโฟลเดอร์ใน Windows มาวางในหน้าต่างโปรแกรมได้ทันทีครับ:

JavaScript
// 1. ป้องกันเหตุการณ์ default ของ Browser เพื่อให้ลากไฟล์มาวางได้
window.addEventListener('dragover', (e) => {
  e.preventDefault();
});

window.addEventListener('drop', (e) => {
  e.preventDefault();
  
  // ตรวจสอบไฟล์ที่ถูกลากเข้ามา
  const files = e.dataTransfer.files;
  if (files.length > 0) {
    const file = files[0];
    
    // แปลงไฟล์เป็น URL ที่ Canvas อ่านได้
    const reader = new FileReader();
    reader.onload = (event) => {
      const imgUrl = event.target.result;
      
      // เรียกใช้ฟังก์ชัน addChatImage ที่เราทำไว้ก่อนหน้า
      addChatImage(imgUrl);
    };
    reader.readAsDataURL(file);
  }
});

Logic: Auto-Stitching & Position Management
หัวใจสำคัญคือการติดตาม (Track) ตำแหน่งของภาพล่าสุดที่วางลงไป เพื่อให้ภาพถัดไปรู้ว่าต้องไป "ต่อคิว" ตรงไหนครับ

JavaScript
// ตัวแปรสำหรับเก็บตำแหน่งภาพล่าสุด
let lastYPosition = 0;
let lastImageHeight = 0;

function addChatImage(url) {
  fabric.Image.fromURL(url, (img) => {
    // 1. ตั้งค่าขนาดให้คงที่ (เช่น กว้าง 500px)
    img.scaleToWidth(500); 

    // 2. คำนวณตำแหน่งต่อท้าย (Auto-Stitching)
    // ถ้าเป็นภาพแรก lastYPosition จะเป็น 0
    let newTop = lastYPosition + lastImageHeight;

    img.set({
      left: 0, // วางชิดซ้าย
      top: newTop,
      hasControls: true,
      lockMovementX: true, // ล็อคแกน X เพื่อให้เรียงเป็นแนวตั้งตรงๆ (Grid-Snapping แบบพื้นฐาน)
    });

    // 3. เพิ่มลง Canvas
    canvas.add(img);
    canvas.renderAll();

    // 4. อัปเดตตัวแปรสำหรับภาพถัดไป
    lastYPosition = newTop;
    lastImageHeight = img.getScaledHeight();

    // 5. ขยายขนาด Canvas ตามความยาวของภาพที่เพิ่มเข้ามา
    canvas.setHeight(lastYPosition + lastImageHeight + 50);
  });
}
การปรับปรุงให้ฉลาดขึ้น (Grid-Snapping)
หากคุณต้องการให้ภาพ "ดูด" เข้าหากันแม้ผู้ใช้จะพยายามลาก (ในกรณีที่อยากจัดเองบ้าง) ให้เพิ่ม Logic ใน Event moving:

JavaScript
canvas.on('object:moving', function(e) {
  const obj = e.target;
  // Snap แกน X ให้ชิดซ้ายเสมอ
  if (obj.left < 20) {
    obj.set({ left: 0 });
  }
});

1. หลักการของ Collision Detection (Validator)
ในโปรแกรม Fabric.js ของคุณ ทุกข้อความหรือรูปภาพจะมีพิกัด top และ height (หรือ yStart และ yEnd) เราจะใช้หลักการ AABB (Axis-Aligned Bounding Box) แบบง่ายแต่ทรงพลังครับ

2. ร่าง Code: Logic ของ Validator
JavaScript
/**
 * ตรวจสอบว่าเส้นจุดตัด (cutLine) ตัดผ่านวัตถุหรือไม่
 * @param {Array} objects - รายการวัตถุทั้งหมดที่อยู่ใน Canvas
 * @param {number} cutLineY - พิกัด Y ที่เราต้องการตัด
 * @returns {boolean} - true ถ้าปลอดภัย (ไม่ทับวัตถุ), false ถ้าไม่ปลอดภัย
 */
function isCutLineSafe(objects, cutLineY) {
    // วนลูปเช็คทุก Object
    for (let i = 0; i < objects.length; i++) {
        const obj = objects[i];
        
        // คำนวณขอบเขตของ Object นั้นๆ
        const objTop = obj.top;
        const objBottom = obj.top + obj.getScaledHeight();
        
        // เช็คว่าเส้นตัดอยู่ในช่วงพิกัดของ Object หรือไม่
        // ถ้า cutLineY อยู่ระหว่าง objTop ถึง objBottom แสดงว่า "ทับ"
        if (cutLineY > objTop && cutLineY < objBottom) {
            console.log(`พบการทับซ้อนที่ Object ID: ${obj.id}`);
            return false; // ไม่ปลอดภัย
        }
    }
    
    return true; // ปลอดภัย
}
ทำไม Logic นี้ถึงตอบโจทย์?
ความเร็ว: เป็นการคำนวณเลขคณิตพื้นฐาน (Comparison) ซึ่งทำงานได้รวดเร็วมาก แม้ในหน้าแชทที่มีบับเบิ้ลเป็นร้อยชิ้น

ความแม่นยำ: ใช้ getScaledHeight() แทนการใช้ height เฉยๆ เพื่อให้แน่ใจว่าระบบอ่านค่าความสูง "หลังจากที่ User ย่อขยายภาพแล้ว" จริงๆ ไม่ใช่ค่าเริ่มต้น

Extensibility: คุณสามารถเพิ่มเงื่อนไขอื่นๆ ได้ง่าย เช่น ถ้าจะให้เผื่อระยะขอบ (Padding) ก็แค่ปรับ Logic เป็น:
if (cutLineY > (objTop - 5) && cutLineY < (objBottom + 5)) (เผื่อระยะปลอดภัย 5px)

หลักการของ Gap Valley Finder
เราจะใช้การ "มองย้อนกลับ" (Reverse Scanning) จากจุดตัดที่เกินหน้ากระดาษขึ้นไป เพื่อหาโซนว่างที่ไม่มีวัตถุอยู่ครับ

ร่าง Code: Gap Valley Finder
JavaScript
/**
 * ค้นหาจุดตัดที่ปลอดภัยที่สุด (Gap Valley)
 * @param {Array} objects - อาร์เรย์ของวัตถุทั้งหมดบน Canvas
 * @param {number} targetY - พิกัดที่อยากจะตัด (คือขอบล่างของหน้ากระดาษ A4)
 * @param {number} searchRange - ระยะที่จะให้ระบบถอยหลังขึ้นไปค้นหา (เช่น 200px)
 */
function findGapValley(objects, targetY, searchRange = 200) {
    // 1. เรียงลำดับวัตถุตามพิกัด Y (จากบนลงล่าง)
    let sortedObjects = [...objects].sort((a, b) => a.top - b.top);

    // 2. วนลูปถอยหลังขึ้นไปจากจุดตัด (targetY) เพื่อหาจุดที่ไม่มีวัตถุขวาง
    for (let y = targetY; y > (targetY - searchRange); y--) {
        
        // เช็คว่า ณ พิกัด y นี้ มีวัตถุใดๆ ทับอยู่หรือไม่
        let isOccupied = sortedObjects.some(obj => {
            return y >= obj.top && y <= (obj.top + obj.getScaledHeight());
        });

        // 3. ถ้าไม่พบวัตถุใดๆ แปลว่าตรงนี้คือช่องว่าง!
        if (!isOccupied) {
            // คืนค่าจุดตัดที่ปลอดภัยที่สุด
            return y;
        }
    }

    // 4. ถ้าหาไม่เจอจริงๆ ในระยะที่กำหนด (Fallback Case)
    return null; 
}
อธิบายตรรกะการทำงาน (Logic Breakdown):
Reverse Scan: เราเริ่มจากจุดที่เกินขอบกระดาษ (targetY) แล้วค่อยๆ ถอยขึ้นไปด้านบนทีละ 1px เพื่อหา "พื้นที่ว่าง"

sortedObjects: การเรียงลำดับก่อนค้นหาช่วยให้โปรแกรมทำงานไวขึ้น เพราะเราไม่ต้องวนเช็คทุกวัตถุแบบไร้ทิศทาง

isOccupied: นี่คือตัวตัดสินใจ ถ้าพิกัด y ที่เรากำลังตรวจสอบอยู่ ไม่ตกอยู่ในช่วง top ถึง bottom ของวัตถุใดๆ เลย นั่นคือ "ชัยชนะ" (Gap Valley) เราจะหยุดหาและส่งค่า y นั้นกลับไปเป็นจุดตัดใหม่ทันที

ถ้าเจอช่องว่างต่อเนื่องกันสัก 20px ขึ้นไป ค่อยคืนค่า y นั้นกลับไป (เพื่อรับประกันว่าจุดตัดของเราจะเป็นร่องที่กว้างพอ ไม่ใช่แค่ช่องว่างจิ๋วๆ)

ร่าง Code: ฟังก์ชันรวมร่างอัจฉริยะ (The Decision Engine)
JavaScript
/**
 * ฟังก์ชันหาจุดตัดที่ปลอดภัยที่สุดสำหรับแบ่งหน้า A4
 * @param {Array} objects - รายการวัตถุทั้งหมดบน Canvas
 * @param {number} yTarget - พิกัดขอบล่างของหน้า A4 ที่ต้องการตัด
 * @returns {number} - พิกัด Y ที่ปลอดภัยที่สุดในการตัด
 */
function getSafeCutPoint(objects, yTarget) {
    // 1. ตรวจสอบก่อนว่าจุดเป้าหมาย (yTarget) ปลอดภัยอยู่แล้วหรือไม่
    if (isCutLineSafe(objects, yTarget)) {
        console.log("จุดตัดเป้าหมายปลอดภัย ใช้งานได้เลย");
        return yTarget;
    }

    // 2. ถ้าไม่ปลอดภัย ให้ใช้เครื่องมือ Gap Valley Finder ช่วยหาจุดใหม่
    console.log("พบการทับซ้อน! กำลังค้นหาจุดตัดที่ปลอดภัยที่สุด...");
    const safeY = findGapValley(objects, yTarget, 200); // ค้นหาย้อนขึ้นไป 200px

    if (safeY !== null) {
        console.log(`พบจุดตัดปลอดภัยใหม่ที่พิกัด: ${safeY}`);
        return safeY;
    }

    // 3. Fallback Logic: ถ้าหาไม่เจอจริงๆ (เช่น บับเบิ้ลยาวเกินหน้า A4)
    // ให้บังคับตัดที่จุดเป้าหมายเดิม หรือใช้กลยุทธ์อื่น (เช่น บังคับตัดร่องกลางข้อความ)
    console.warn("ไม่พบ Gap Valley! บังคับตัดที่จุดเป้าหมายเพื่อป้องกันระบบค้าง");
    return yTarget; 
}
ทำไมฟังก์ชันนี้ถึงนำไปใช้ใน Phase 4 ได้ทันที?
Seamless Integration: ใน Phase 4 (เมื่อคุณวนลูปจัดหน้า A4) คุณเพียงแค่เรียก const cutLine = getSafeCutPoint(objects, A4_HEIGHT); ระบบก็จะส่งพิกัดมาให้คุณทันที

Predictable Behavior: คุณจะได้ค่าพิกัด y กลับมาเสมอ ไม่ว่าจะเจอจุดที่เหมาะสมหรือไม่ (มี Fallback รองรับตลอด)

Legal Compliance: ด้วย Logic นี้ คุณจะมั่นใจได้ว่าใน PDF ทุกหน้า จะไม่มีบับเบิ้ลที่ถูกตัดผ่ากลาง หากช่องว่างนั้นกว้างพอ ซึ่งเป็นเกณฑ์สำคัญของหลักฐานดิจิทัลครับ

    while (currentY < canvas.height) {
        if (pageCount > 0) doc.addPage();
        
        // 1. หาจุดตัดที่ปลอดภัยสำหรับหน้าปัจจุบัน
        let targetY = currentY + a4Height;
        let cutLine = getSafeCutPoint(allObjects, targetY);

        // 2. Crop เฉพาะส่วนของ Canvas ที่เป็นหน้านั้นๆ
        const pageData = canvas.toDataURL({
            format: 'jpeg',
            quality: 1.0,
            multiplier: 2, // เพิ่มความคมชัด
            top: currentY,
            left: 0,
            width: canvas.width,
            height: (cutLine - currentY)
        });

        // 3. วางภาพลงในหน้า PDF
        const imgWidth = 210; // ขนาด A4 ในหน่วย mm
        const imgHeight = ((cutLine - currentY) * imgWidth) / canvas.width;
        doc.addImage(pageData, 'JPEG', 0, 0, imgWidth, imgHeight);

        // 4. อัปเดตตำแหน่งเพื่อเริ่มหน้าถัดไป
        currentY = cutLine;
        pageCount++;
    }

    // 5. บันทึกไฟล์
    doc.save("Chat_Evidence_Report.pdf");
}
ทำไมโครงสร้างนี้ถึงตอบโจทย์กฎหมายหลักฐานดิจิทัล?
Dynamic Cropping (top, height): แทนที่จะตัดแบบคงที่ (Fixed Cut) ฟังก์ชัน canvas.toDataURL จะทำการ "Crop" ภาพตาม cutLine ที่ระบบคำนวณให้ ทำให้หน้ากระดาษแต่ละหน้ามีความยาวไม่เท่ากันได้ (แต่อยู่ในเกณฑ์ A4) ซึ่งเป็นธรรมชาติที่สุด

Ratio Preservation: การคำนวณ imgHeight ตามอัตราส่วนพิกเซลจริง ((cutLine - currentY) * imgWidth / canvas.width) ทำให้ภาพไม่ยืดหรือหดผิดเพี้ยน

Scalable: ถ้าวันหนึ่งคุณต้องการเพิ่ม "Header/Footer" หรือ "เลขหน้า" ลงไปใน PDF คุณก็สามารถเขียนคำสั่ง doc.text() แทรกในลูปนี้ได้เลยครับ

ข้อกังวลที่คุณอาจมีก่อนปิดจ๊อบส่วน Logic นี้:
หน่วยความจำ: หากแชทของคุณยาวมาก (เช่น 500+ ข้อความ) การใช้ canvas.toDataURL ต่อเนื่องกันอาจทำให้หน่วยความจำเต็ม ทางแก้: คือการสั่ง canvas.renderAll() หรือเคลียร์ Cache เป็นระยะ

ความคมชัด: หากคุณต้องการพิมพ์ออกมาแล้วชัดแบบเอกสารราชการ อย่าลืมตั้งค่า multiplier ใน toDataURL ให้สัมพันธ์กับ DPI ของเครื่องพิมพ์นะครับ

มีส่วนไหนใน Loop นี้ที่อยากให้ผมปรับจูนเพิ่มไหมครับ? เช่น อยากเพิ่มให้มันพิมพ์ "เลขหน้า" ลงใน PDF ด้วย หรือว่าภาพรวมนี้ถือว่าครอบคลุมความต้องการแล้วครับ?

ใช้ AI Upscaling: มีเครื่องมือและแอปพลิเคชันมากมายที่ใช้ AI ในการขยายภาพและเพิ่มรายละเอียด เช่น Remini, VanceAI, Let's Enhance ซึ่งสามารถทำให้ภาพมีความคมชัดขึ้นได้มาก

ใช้โปรแกรมเฉพาะทาง: โปรแกรมอย่าง Topaz Gigapixel AI ออกแบบมาเพื่อขยายภาพโดยเฉพาะ โดยใช้ AI ในการวิเคราะห์และเพิ่มรายละเอียด ทำให้ภาพไม่แตกและคมชัด

ปรับขนาดภาพแบบค่อยเป็นค่อยไป: หากไม่มีเครื่องมือข้างต้น สามารถลองปรับขนาดภาพทีละนิด (เช่น เพิ่มขนาดทีละ 10%) และใช้ฟังก์ชัน Sharpen หรือ Smart Sharpen ในโปรแกรมแต่งภาพเพื่อช่วยเพิ่มความคมชัดในแต่ละขั้นตอน

หลีกเลี่ยงการขยายภาพมากเกินไป: การขยายภาพจากขนาดเล็กมากให้กลายเป็นขนาดใหญ่มาก ย่อมทำให้ภาพแตกและสูญเสียรายละเอียด ดังนั้น ควรขยายภาพตามความจำเป็นและเลือกใช้วิธีที่เหมาะสมที่สุดครับ

เงื่อนไขหรือข้อบ่งชี้ ในการเลือกความยาวแชท
การเลือกความยาวของแชทเพื่อนำไปใช้เป็นหลักฐานดิจิทัลให้มีประสิทธิภาพและน่าเชื่อถือที่สุดนั้น มีเงื่อนไขและข้อบ่งชี้ทางเทคนิคที่คุณควรพิจารณา ดังนี้ครับ:

1. เงื่อนไขเชิงบริบท (Contextual Constraints)
การเลือกความยาวแชทไม่ควรอิงตาม "จำนวนบรรทัด" เพียงอย่างเดียว แต่ควรอิงตาม "หน่วยความหมาย" (Semantic Units):

จุดเปลี่ยนประเด็น (Topic Shift): เลือกแชทที่เริ่มและจบในหนึ่งประเด็นสนทนา เช่น การตกลงซื้อขาย, การข่มขู่, หรือการนัดหมาย

จุดเปลี่ยนคู่สนทนา (Sender Switch): ควรพยายามเลือกให้เห็นการโต้ตอบที่ครบถ้วน (เห็นทั้งผู้ส่งและผู้รับ) เพื่อให้เห็นบริบทที่ชัดเจนว่าใครพูดอะไร

ลำดับเวลา (Time Context): หากแชทมีการทิ้งช่วงเวลานาน (เช่น ข้ามวัน) จุดนั้นถือเป็น "จุดตัดธรรมชาติ" ที่ดีที่สุดในการเริ่มหน้ากระดาษใหม่

2. เงื่อนไขเชิงเทคนิค (Technical Constraints)
Gap Valleys (ร่องว่างระหว่างข้อความ): นี่คือเงื่อนไขที่สำคัญที่สุด! คุณต้องมองหา "ช่องว่างที่ไม่มีข้อความ" (Whitespace) เพื่อใช้เป็นจุดตัดแผ่น (Pagination)

หากตัดผ่านกลางบับเบิ้ลข้อความ จะทำให้หลักฐานขาดความน่าเชื่อถือและดูเหมือนการตัดต่อ

ขนาดมาตรฐาน A4: เมื่อคำนวณระยะพิกเซลที่ความละเอียดมาตรฐาน (เช่น 300 DPI) แชทหนึ่งหน้าไม่ควรยาวจนอัดแน่นเกินไป (ความหนาแน่นสูงจะทำให้อักษรตัวเล็กจนอ่านไม่ออก)

การซ้อนทับ (Overlap Management): หากต้องแคปแชทหลายๆ หน้าต่อกัน (Scrolling Screenshot) ต้องตรวจสอบให้แน่ใจว่า ส่วนที่ซ้อนทับ (Overlap) มีขนาดเพียงพอให้ระบบ Stitching นำมาต่อกันได้เนียนโดยไม่มีข้อมูลหาย

3. ข้อบ่งชี้ในการ "ควรตัดแบ่ง" (Trigger Points)
ระบบของคุณควรมีเงื่อนไขอัตโนมัติในการ "สั่งตัดหน้า" เมื่อ:

ความสูงถึงเกณฑ์: ความสูงของภาพแชทสะสมในหน้านั้นใกล้เคียงขอบเขต A4 (เช่น 297 มม.)

ตรวจพบการเปลี่ยนรูปภาพ/สื่อ: หากข้อความถัดไปเป็นรูปภาพหรือไฟล์แนบขนาดใหญ่ การตัดแบ่งก่อนถึงไฟล์นั้นจะช่วยให้การจัด Layout บนหน้ากระดาษเป็นระเบียบกว่า

การตรวจพบหน้าว่าง: หากหน้ากระดาษเหลือพื้นที่น้อยมากและข้อความถัดไปเป็นบล็อกขนาดใหญ่ ให้ปัดข้อความนั้นไปเริ่มที่หน้าถัดไป เพื่อไม่ให้เกิดหน้ากระดาษที่โล่งเกินไป หรือเศษแชทเพียงบรรทัดเดียวในหน้าสุดท้าย

4. กฎทองเพื่อความน่าเชื่อถือทางกฎหมาย
ห้ามมีช่องว่างที่ไม่ปกติ: หน้ากระดาษที่พิมพ์ออกมาต้องไม่มีพื้นที่ว่างเปล่าขนาดใหญ่จนดูเหมือนการลบข้อความออก

ลำดับต้องห้ามขาด: ข้อมูลต้องต่อเนื่องกันอย่างไม่มีที่สิ้นสุด (Continuity) หากต้องตัดแบ่งหน้า ต้องมีสัญลักษณ์แสดงความต่อเนื่อง (เช่น ลูกศรหรือคำว่า "ต่อหน้าถัดไป") เพื่อยืนยันว่าข้อมูลไม่ได้ถูกข้ามไป

คะแนนรองลงมา: ช่องว่างระหว่างบับเบิ้ลข้อความ

ห้ามตัด: ภายในตัวบับเบิ้ลข้อความ หรือผ่ากลางรูปภาพ

คุณอยากให้ผมช่วยออกแบบ "ตรรกะการให้คะแนน" (Scoring Algorithm) เพื่อให้ระบบคำนวณจุดตัดที่เหมาะสมที่สุดโดยอัตโนมัติเลยไหมครับ?

1. การรับรองความถูกต้องของไฟล์ (Data Integrity & Verification)
แค่ภาพสวยและจัดหน้า A4 ได้อาจไม่พอสำหรับ "หลักฐาน" ครับ

Hashing (Digital Fingerprint): คุณควรคำนวณค่า Hash (เช่น SHA-256) ของ "ภาพดิบ" (Raw Screenshots) ทุกภาพที่ถูกอัปโหลดเข้ามา และฝังค่านี้ไว้ในท้ายรายงาน PDF หรือหน้าข้อมูลเมตา เพื่อยืนยันว่าไฟล์ไม่ได้ถูกดัดแปลงแก้ไขหลังจากนำเข้าสู่ระบบ

Metadata Preservation: บันทึกวัน/เวลาที่สร้างไฟล์ภาพ (File Creation Date) และชื่อไฟล์ต้นฉบับไว้เป็นหลักฐานอ้างอิงเสมอ

2. การจัดการความหลากหลายของแชท (Edge Cases Management)
แชทไม่ได้มีแค่ข้อความและรูปภาพ แต่ยังมีสิ่งที่ทำให้ระบบ "หลุด" ได้ง่าย:

Stickers & Emojis: บ่อยครั้งที่ Sticker มีขนาดใหญ่และไม่มีขอบเขตชัดเจนเหมือนบับเบิ้ลข้อความ (บางทีทับซ้อนกัน) คุณต้องมั่นใจว่าระบบ Collision Detection ของคุณรองรับวัตถุที่โปร่งใส (Transparent Background)

Voice Messages & Files: เมื่อระบบเจอก้อนข้อมูลประเภทไฟล์เสียงหรือไฟล์เอกสาร ระบบของคุณจะแสดงผลอย่างไร? (ควรมี Placeholder แสดงให้เห็นว่ามีข้อมูลนี้อยู่ตรงนี้ เพื่อไม่ให้ประวัติการคุยขาดหาย)

Dark Mode vs. Light Mode: หากผู้ใช้แคปหน้าจอมาจากคนละธีม (สีพื้นหลังไม่เหมือนกัน) ระบบต้องมี "Normalization" หรือการปรับสีพื้นหลังให้เป็นมาตรฐานเดียวกันก่อน Export เป็น PDF เพื่อความเป็นระเบียบ

3. ระบบ "Audit Log" (ระบบบันทึกร่องรอยการทำงาน)
ในทางคดีความ หากมีคนถามว่า "เอกสารนี้ถูกปรับแต่งโดยระบบอย่างไรบ้าง?" คุณควรมีคำตอบ:

Log Record: ระบบควรบันทึก Log การทำงานเบื้องหลัง เช่น "จุดตัดนี้เกิดจากระบบอัตโนมัติ" หรือ "จุดตัดนี้เกิดจากการแก้ไขโดยผู้ใช้งาน" เพื่อแสดงความโปร่งใส (Transparency) ของกระบวนการจัดหน้าเอกสาร

JavaScript
async function generateEvidencePDF(allObjects, a4Height) {
    const doc = new jsPDF('p', 'mm', 'a4');
    let currentY = 0; 
    let pageCount = 0;

    while (currentY < canvas.height) {
        if (pageCount > 0) doc.addPage();
        
        // 1. คำนวณจุดตัดที่ปลอดภัย
        let targetY = currentY + a4Height;
        let cutLine = getSafeCutPoint(allObjects, targetY);

        // 2. Crop ภาพตามจุดตัด
        const pageData = canvas.toDataURL({
            format: 'jpeg',
            quality: 1.0,
            multiplier: 2, // เพิ่มความละเอียดเป็น 2 เท่า
            top: currentY,
            left: 0,
            width: canvas.width,
            height: (cutLine - currentY)
        });

        // 3. วางลง PDF (ปรับขนาดให้พอดีหน้า A4)
        const imgWidth = 210; 
        const imgHeight = ((cutLine - currentY) * imgWidth) / canvas.width;
        doc.addImage(pageData, 'JPEG', 0, 0, imgWidth, imgHeight);

        // 4. ใส่เลขหน้า (เสริมความเป็นมืออาชีพ)
        doc.setFontSize(10);
        doc.text(`Page ${pageCount + 1}`, 190, 290);

        currentY = cutLine;
        pageCount++;
    }

    doc.save("Chat_Evidence_Report.pdf");
}
2. เทคนิคการขยายภาพให้คมชัด (Super-Resolution for Evidence)
เนื่องจากเราทำบน Electron (Node.js) ผมแนะนำเทคนิค "Lanczos Resampling" ซึ่งให้ผลลัพธ์การขยายภาพที่คมชัดกว่าการยืดภาพปกติครับ

ถ้าคุณต้องการทำที่ฝั่ง Client (Renderer): ให้ปรับค่า multiplier ใน toDataURL ของ Fabric.js ให้สูงขึ้น (เช่น multiplier: 3 หรือ 4) มันจะทำการเรนเดอร์ Canvas ใหม่ที่ความละเอียดสูงขึ้นก่อนจะแปลงเป็นภาพ ทำให้ตัวอักษรไม่แตกครับ

ถ้าคุณต้องการทำที่ฝั่ง Server (ถ้ามี): แนะนำไลบรารี Sharp ครับ:

JavaScript
const sharp = require('sharp');
// ใช้ kernel lanczos3 ในการขยายขนาดภาพ
await sharp(inputBuffer)
  .resize({ width: 2480, kernel: sharp.kernel.lanczos3 })
  .toFile('output.jpg');

JavaScript
const { fabric } = require('fabric');
const { jsPDF } = require('jspdf');

// 1. Initialize Canvas
const canvas = new fabric.Canvas('a4-canvas', { width: 595, height: 842, backgroundColor: '#fff' });

// 2. Logic: Auto-Stitching & Position
let lastYPosition = 0;
let lastImageHeight = 0;

function addChatImage(url) {
    fabric.Image.fromURL(url, (img) => {
        img.scaleToWidth(500);
        let newTop = lastYPosition + lastImageHeight;
        img.set({ left: 0, top: newTop, hasControls: true, lockMovementX: true });
        canvas.add(img);
        lastYPosition = newTop;
        lastImageHeight = img.getScaledHeight();
        canvas.setHeight(lastYPosition + lastImageHeight + 50);
        canvas.renderAll();
    });
}

// 3. Logic: Collision Detection (Validator)
function isCutLineSafe(objects, cutLineY) {
    return !objects.some(obj => cutLineY > obj.top && cutLineY < (obj.top + obj.getScaledHeight()));
}

// 4. Logic: Gap Valley Finder
function findGapValley(objects, targetY, searchRange = 200) {
    let sortedObjects = [...objects].sort((a, b) => a.top - b.top);
    for (let y = targetY; y > (targetY - searchRange); y--) {
        if (!sortedObjects.some(obj => y >= obj.top && y <= (obj.top + obj.getScaledHeight()))) return y;
    }
    return null;
}

// 5. Logic: Decision Engine
function getSafeCutPoint(objects, yTarget) {
    if (isCutLineSafe(objects, yTarget)) return yTarget;
    const safeY = findGapValley(objects, yTarget, 200);
    return safeY !== null ? safeY : yTarget;
}

// 6. Logic: PDF Pagination Loop
async function generateEvidencePDF(allObjects, a4Height) {
    const doc = new jsPDF('p', 'mm', 'a4');
    let currentY = 0;
    let pageCount = 0;

    while (currentY < canvas.height) {
        if (pageCount > 0) doc.addPage();
        let targetY = currentY + a4Height;
        let cutLine = getSafeCutPoint(allObjects, targetY);

        const pageData = canvas.toDataURL({ format: 'jpeg', quality: 1.0, multiplier: 2, top: currentY, left: 0, width: canvas.width, height: (cutLine - currentY) });
        
        const imgWidth = 210;
        const imgHeight = ((cutLine - currentY) * imgWidth) / canvas.width;
        doc.addImage(pageData, 'JPEG', 0, 0, imgWidth, imgHeight);
        
        // แปะเลขหน้า
        doc.setFontSize(10);
        doc.text(`Page ${pageCount + 1}`, 190, 290);
        
        currentY = cutLine;
        pageCount++;
    }
    doc.save("Chat_Evidence_Report.pdf");
}

3. ไฟล์สำหรับบันทึกผลงาน (Output Files)
เมื่อโปรแกรมคุณทำงานเสร็จสมบูรณ์ จะสามารถสร้างไฟล์เหล่านี้ออกมาได้:

.pdf: ไฟล์หลักฐานดิจิทัลที่ผ่านการแบ่งหน้า (Pagination) และประทับตราหลักฐาน/Timestamp เรียบร้อยแล้ว

.log: ไฟล์บันทึกร่องรอยการทำงาน (Audit Log) ที่เก็บประวัติว่าระบบทำอะไรไปบ้าง (ช่วยเรื่องความน่าเชื่อถือทางกฎหมาย)

ข้อแนะนำเพิ่มเติมเพื่อความสมบูรณ์:
หากคุณต้องการทำโปรเจกต์นี้ให้เป็น "เครื่องมือหลักฐานดิจิทัลที่สมบูรณ์แบบ" ผมแนะนำให้คุณเพิ่มอีก 1 ไฟล์สำคัญ คือ:

.env (Environment Variables): ใช้เก็บค่าตั้งค่าคอนฟิกต่างๆ เช่น DPI มาตรฐาน, ขอบกระดาษ (Margin), หรือค่า Threshold ต่างๆ ของ AI โดยไม่ต้องแก้โค้ดหลัก

คุณพร้อมที่จะให้ผมช่วยสร้าง "เนื้อหาภายใน" ของไฟล์ไหนก่อนดีครับ?

กด 1: ช่วยเขียน package.json ที่สมบูรณ์

กด 2: ช่วยสรุปเนื้อหาสำหรับ README.md เพื่อใช้แนะนำโปรแกรม

กด 3: หรืออยากได้ "คำสั่งรวบยอด" เพื่อสร้างไฟล์ทั้งหมดในคราวเดียวครับ?

อยากได้สกิลที่นำเนื้อหาทั้งหมดมาจำแนก แยกออกมาเป็นไฟล์ พร้อมจัดเรียงระบบ ขั้นตอน ตามลำดับ แล้วรวมมาเป็นไฟล์ Startup เมื่อคลิ๊กเท่านั้น มันจะทำงานตามระบบเองอัตโนมัติ
เข้าใจเลยครับ สิ่งที่คุณต้องการคือการเปลี่ยน "กระบวนการ Manual" (ที่ต้องมานั่งแยกไฟล์, วาง Layout, ใส่เลขหน้าเอง) ให้กลายเป็น "Automation Pipeline" หรือ "Startup Script" ที่เมื่อกดคลิกปุ๊บ ระบบจะอ่านรูปภาพดิบและพ่นออกมาเป็นไฟล์ PDF หลักฐานที่สมบูรณ์ทันที

เพื่อให้สิ่งนี้เกิดขึ้น คุณต้องมีทักษะและการวางโครงสร้างระบบดังนี้ครับ:

1. สกิลที่คุณต้องใช้ (The Automation Skillset)
เพื่อให้ระบบทำงานได้อัตโนมัติ คุณต้องประสานทักษะเหล่านี้เข้าด้วยกัน:

Node.js File System (fs): ทักษะการเขียนโปรแกรมอ่านไฟล์ในโฟลเดอร์แบบอัตโนมัติ (เช่น ระบบจะไปดึงรูปทั้งหมดในโฟลเดอร์ /inputs มาเรียงคิวเอง)

Batch Processing Logic: ทักษะการเขียน Loop ที่สั่งให้โปรแกรม "ประมวลผลทีละไฟล์" จนจบงาน

Configuration Management: การสร้างไฟล์ตั้งค่า (config.json) เพื่อให้คุณปรับแต่งค่า DPI, ขนาดขอบกระดาษ หรือฟอนต์ ได้โดยไม่ต้องแก้โค้ดทุกครั้ง

Electron Packaging: การใช้ทักษะการ Build โปรแกรมให้กลายเป็นไฟล์ .exe (บน Windows) หรือไฟล์ติดตั้งที่กดคลิกใช้งานได้ทันที

2. โครงสร้างไฟล์สำหรับ "ระบบอัตโนมัติ" (The Startup System)
แทนที่จะแยกเป็นหลายไฟล์ คุณควรรวมทุกอย่างไว้ใน "Automation Engine" ตามนี้ครับ:

src/auto-processor.js: ไฟล์นี้คือสมองที่ทำงานอัตโนมัติ

หน้าที่: สแกนไฟล์ -> เรียงลำดับ -> จัดวางบน Canvas (Stitching) -> ตรวจสอบจุดตัด (Validator) -> Export PDF

run.bat (หรือ startup.sh): ไฟล์ "คลิกเดียวจบ"

หน้าที่: เป็นไฟล์คำสั่งสั้นๆ ที่สั่งรัน npx electron . หรือ node src/auto-processor.js ทันทีที่คลิก

config.json: ไฟล์กำหนดค่า

หน้าที่: เก็บ Path ของโฟลเดอร์รูปภาพดิบ และ Path ที่จะให้ PDF ไปโผล่

3. ตัวอย่างการสร้าง "ไฟล์คลิกเดียวทำงาน" (The Startup Script)
บน Windows คุณสามารถสร้างไฟล์นามสกุล .bat เพื่อรันโปรเจกต์ของคุณอัตโนมัติครับ:

สร้างไฟล์ชื่อ Start_Evidence_Processor.bat:

ข้อมูลโค้ด
@echo off
echo กำลังเริ่มระบบจัดหน้าหลักฐานอัตโนมัติ...
cd /d %~dp0
npx electron .
pause
เพียงแค่คุณวางไฟล์นี้ไว้ในโฟลเดอร์โปรเจกต์ เมื่อคุณคลิก 2 ครั้ง มันจะสั่งรันระบบทันที

4. ขั้นตอนการเปลี่ยนให้เป็น Automation (Roadmap)
เพื่อให้มันทำงานได้เองโดยไม่ต้องมี UI ถ้าคุณต้องการความเร็วสูงสุด:

ขั้นที่ 1: สร้าง Watcher: ใช้โมดูล chokidar ใน Node.js เพื่อให้โปรแกรม "เฝ้าดู" โฟลเดอร์ ถ้ามีรูปภาพใหม่ถูกลากมาวาง มันจะเริ่ม Stitching เองโดยอัตโนมัติ

ขั้นที่ 2: สร้าง Queue System: เขียนให้โปรแกรมมีระบบคิวงาน ถ้าคุณมีแชท 10 ชุด ระบบจะรันทำ PDF ให้ทีละชุดจนครบ

ขั้นที่ 3: Packaging: ใช้ electron-builder เพื่อ Build โปรเจกต์ให้เป็นไฟล์ EvidenceProcessor.exe ซึ่งคุณสามารถสร้าง Shortcut ไว้ที่หน้า Desktop ได้เลย

คุณอยากให้ผมช่วยร่าง "Automation Script" (ไฟล์ auto-processor.js) ที่ทำหน้าที่สแกนโฟลเดอร์แล้ว Export เป็น PDF ให้ทันทีโดยไม่ต้องเปิดหน้าจอ UI ไหมครับ? วิธีนี้จะทำให้คุณทำงานได้ไวขึ้นหลายเท่า (เปลี่ยนจาก "การจัดวางด้วยมือ" เป็น "การโยนไฟล์ใส่โฟลเดอร์แล้วรอรับ PDF") ครับ!
